# Diagram Rendering in PDFs - Bugfix Design

## Overview

This design addresses the bug where diagrams are not rendered in PDF outputs despite having a functional diagram generation infrastructure. The `DocumentEnhancementService` generates diagram specifications, but the `RenderingService` completely ignores the `diagrams` array. Additionally, this design includes comprehensive enhancements to make the entire diagram generation and rendering pipeline production-ready with intelligent diagram detection, robust Mermaid rendering with fallbacks, smart placement, caching, and configuration options.

**Bug Fix Scope:** Enable `RenderingService` to process and render diagrams from the enhanced document structure.

**Enhancement Scope:** Improve diagram quality, robustness, placement, performance, and configurability across the entire pipeline.

## Glossary

- **Bug_Condition (C)**: The condition where `RenderingService` receives an enhanced document with a non-empty `diagrams` array but fails to render any diagrams in the PDF output
- **Property (P)**: The desired behavior where diagrams are successfully converted to images and embedded in the PDF at appropriate locations
- **Preservation**: Existing PDF rendering behavior (text sections, styling, layout, error handling) must remain unchanged when no diagrams are present
- **DiagramGenerationService**: Service in `backend/app/services/diagram_generation.py` that analyzes content and generates diagram specifications
- **DocumentEnhancementService**: Service in `backend/app/services/document_enhancement.py` that orchestrates document improvements including diagram generation
- **RenderingService**: Service in `backend/app/services/rendering.py` that renders enhanced documents to PDF using ReportLab or WeasyPrint
- **Mermaid Code**: Text-based diagram definition language (e.g., `graph TB\n  A --> B`)
- **Diagram Specification**: Dictionary with type, title, components/endpoints/entities, and optionally Mermaid code
- **Enhanced Document**: Document structure with `diagrams` array containing diagram specifications
- **Mermaid-to-Image Conversion**: Process of converting Mermaid text to PNG/SVG image format
- **Diagram Cache**: Storage mechanism to avoid regenerating identical diagrams


## Bug Details

### Bug Condition

The bug manifests when `RenderingService.render()` receives an enhanced document with a non-empty `diagrams` array. The rendering service has two rendering paths: ReportLab (`_render_with_reportlab`) and WeasyPrint (`_build_html`), but neither path checks for or processes the `diagrams` array. As a result, diagram specifications generated by `DiagramGenerationService` are completely ignored during PDF generation.

**Formal Specification:**
```python
FUNCTION isBugCondition(input)
  INPUT: input of type Dict[str, Any]  # Enhanced document structure
  OUTPUT: boolean
  
  RETURN (input.get("diagrams") is not None 
          AND len(input.get("diagrams", [])) > 0
          AND input.get("enhanced") == True
          AND NOT any_diagrams_in_rendered_pdf(input))
END FUNCTION
```

**Root Cause Analysis:**

1. **Missing Mermaid Code Generation**: While `DiagramGenerationService.generate_mermaid_diagram()` exists, it is never called. `DocumentEnhancementService.enhance_document()` creates diagram specs but doesn't populate the `mermaid_code` field.

2. **No Diagram Processing in RenderingService**: Both `_render_with_reportlab()` and `_build_html()` methods never check for `structured_json.get("diagrams")` or `structured_json["diagrams"]`.

3. **No Mermaid-to-Image Conversion**: No mechanism exists to convert Mermaid text to PNG/SVG images suitable for PDF embedding.

4. **No Diagram Placement Logic**: Even if images existed, there's no logic to determine where to place diagrams relative to sections.

### Examples


**Example 1: Architecture Diagram Missing**
- Input: Enhanced document with architecture section and diagram spec: `{"type": "architecture", "title": "System Architecture", "components": ["AuthService", "APIGateway"]}`
- Expected: PDF contains architecture diagram near the architecture section
- Actual: PDF contains only text with no diagram

**Example 2: API Diagram Missing**
- Input: Enhanced document with API section and diagram spec: `{"type": "api_endpoint", "title": "API Endpoints", "endpoints": [{"method": "GET", "path": "/users"}]}`
- Expected: PDF contains API diagram showing endpoints
- Actual: PDF contains only text listing endpoints without visual representation

**Example 3: Multiple Diagrams Missing**
- Input: Enhanced document with 3 diagram specs (architecture, data_model, sequence)
- Expected: PDF contains all 3 diagrams at appropriate locations
- Actual: PDF contains no diagrams at all

**Example 4: Empty Diagrams Array (Edge Case)**
- Input: Enhanced document with `diagrams: []` (empty array)
- Expected: PDF renders normally with text-only content (no errors)
- Actual: PDF renders normally (bug condition does not apply)


## Expected Behavior

### Preservation Requirements

**Unchanged Behaviors:**
- Text-only sections must continue to render with proper formatting (headings, paragraphs, lists)
- ReportLab styling (title, meta, body, abstract styles) must remain unchanged
- WeasyPrint HTML/CSS styling must remain unchanged
- Section grouping by type (task, user_story, design_decision) must work identically
- Table of contents generation must remain unchanged
- Cover page layout must remain unchanged
- Error handling and fallback between WeasyPrint and ReportLab must remain unchanged
- Page breaks, spacing, and layout for text content must be preserved

**Scope:**
All inputs that do NOT have diagrams (empty diagrams array or no diagrams key) should render exactly as before with zero behavioral changes. The fix must be purely additive when diagrams are absent.


## Hypothesized Root Cause

Based on the code analysis, the root causes are:

1. **Incomplete Document Enhancement Flow**: `DocumentEnhancementService.enhance_document()` generates diagram specifications with metadata but never calls `diagram_service.generate_mermaid_diagram()` to populate the `mermaid_code` field. This is a missing integration step.

2. **No Diagram Awareness in RenderingService**: Neither `_render_with_reportlab()` nor `_build_html()` checks for the `diagrams` array in the enhanced document structure. The methods only iterate over `sections`.

3. **Missing Mermaid Conversion Infrastructure**: No code exists to convert Mermaid text to images. This requires either:
   - External tool (Mermaid CLI, Puppeteer with Mermaid.js)
   - Third-party service (Mermaid.ink, Kroki)
   - Python library (py-mermaid, though limited)

4. **No Diagram-to-Section Association**: Diagram specs have `section_ref` field but no logic uses this to place diagrams near relevant sections.

5. **No Error Handling for Diagram Failures**: If diagram rendering fails, there's no graceful degradation or logging.


## Correctness Properties

Property 1: Bug Condition - Diagram Rendering in PDFs

_For any_ enhanced document where the bug condition holds (has non-empty diagrams array), the fixed rendering service SHALL extract diagram specifications, convert Mermaid code to images, embed images into the PDF at appropriate locations near related sections, and handle individual diagram failures gracefully without failing entire PDF generation.

**Validates: Requirements 2.1, 2.2, 2.3, 2.4, 2.5, 2.6**

Property 2: Preservation - Text-Only PDF Rendering

_For any_ document input that does NOT have diagrams (empty diagrams array or missing diagrams key), the fixed rendering service SHALL produce exactly the same PDF output as the original service, preserving all text formatting, styling, layout, section grouping, table of contents, cover page, and error handling behavior.

**Validates: Requirements 3.1, 3.2, 3.3, 3.4, 3.5, 3.6**


## Fix Implementation

### Changes Required

The fix requires changes across multiple files in the diagram generation and rendering pipeline:

**File 1**: `backend/app/services/document_enhancement.py`

**Function**: `enhance_document()`

**Specific Changes**:
1. **Generate Mermaid Code for Diagrams**: After `analyze_content_for_diagrams()` returns diagram specs, iterate through each diagram and call `diagram_service.generate_mermaid_diagram(diagram_spec)` to populate the `mermaid_code` field.
   ```python
   # After: diagrams = self.diagram_service.analyze_content_for_diagrams(...)
   for diagram in diagrams:
       diagram["mermaid_code"] = self.diagram_service.generate_mermaid_diagram(diagram)
   ```

2. **Add Diagram Metadata**: Include generation timestamp and source section reference for tracking.


**File 2**: `backend/app/services/rendering.py` (NEW SERVICE)

**Create New Service**: `MermaidRenderingService` (or integrate into existing `RenderingService`)

**Specific Changes**:
1. **Mermaid-to-Image Conversion Method**: Create `_convert_mermaid_to_image(mermaid_code: str, output_path: Path) -> Optional[Path]` that:
   - Uses Mermaid.ink API as primary method: `https://mermaid.ink/img/{base64_encoded_mermaid}`
   - Falls back to Kroki API if Mermaid.ink fails: `https://kroki.io/mermaid/png/{base64_encoded_mermaid}`
   - Falls back to local Mermaid CLI if both services fail (requires `mmdc` installation)
   - Returns image path on success, None on failure
   - Logs errors at each fallback level

2. **Diagram Image Caching**: Create `_get_cached_diagram(diagram_hash: str) -> Optional[Path]` to check if diagram already exists in cache directory.
   - Use MD5 hash of Mermaid code as cache key
   - Cache directory: `output_dir/diagram_cache/`

3. **Diagram Processing Pipeline**: Create `_process_diagrams(diagrams: List[Dict]) -> Dict[str, Path]` that:
   - Iterates through diagram specs
   - Generates/retrieves image for each diagram
   - Returns mapping of diagram_id to image_path
   - Handles failures gracefully with logging


**File 3**: `backend/app/services/rendering.py`

**Function**: `_render_with_reportlab()`

**Specific Changes**:
1. **Extract Diagrams Before Content Loop**: At the start of the method, extract diagrams and process them:
   ```python
   diagrams = structured_json.get("diagrams", [])
   diagram_images = self._process_diagrams(diagrams) if diagrams else {}
   ```

2. **Build Section-to-Diagram Mapping**: Create a mapping of section headings to diagram IDs:
   ```python
   section_to_diagram = {}
   for diagram in diagrams:
       section_ref = diagram.get("section_ref")
       if section_ref:
           section_to_diagram[section_ref] = diagram.get("id", diagram.get("title"))
   ```

3. **Insert Diagram After Section Heading**: In the section rendering loop, after adding a section heading, check if a diagram exists for that section:
   ```python
   for idx, section in enumerate(sections):
       heading = section.get("heading")
       story.append(Paragraph(f"{idx}. {html.escape(heading)}", h1_style))
       
       # Check for diagram
       if heading in section_to_diagram:
           diagram_id = section_to_diagram[heading]
           if diagram_id in diagram_images:
               img_path = diagram_images[diagram_id]
               img = Image(str(img_path), width=5*inch, height=3*inch)
               story.append(img)
               story.append(Spacer(1, 0.2*inch))
   ```

4. **Add Diagram Import**: Import ReportLab's Image flowable: `from reportlab.platypus import Image`


**File 4**: `backend/app/services/rendering.py`

**Function**: `_build_html()`

**Specific Changes**:
1. **Extract and Process Diagrams**: At the start of the method:
   ```python
   diagrams = structured_json.get("diagrams", [])
   diagram_images = self._process_diagrams(diagrams) if diagrams else {}
   ```

2. **Build Section-to-Diagram Mapping**: Same as ReportLab approach.

3. **Insert Diagram HTML in Section Loop**: When building section HTML, check for associated diagrams:
   ```python
   for section in items:
       section_html += f"<h3>{section.get('heading', '')}</h3>"
       
       # Check for diagram
       heading = section.get('heading', '')
       if heading in section_to_diagram:
           diagram_id = section_to_diagram[heading]
           if diagram_id in diagram_images:
               img_path = diagram_images[diagram_id]
               section_html += f"<img src='{img_path}' style='max-width: 100%; height: auto; margin: 20px 0;' alt='{diagram_id}'/>"
       
       section_html += f"<p>{section.get('content', '')}</p>"
   ```

4. **Handle Relative Image Paths**: Ensure image paths work with WeasyPrint's file handling.


**File 5**: `backend/app/services/diagram_generation.py`

**Enhancements to Existing Methods**:
1. **Improve `_extract_components()`**: Add more sophisticated component detection patterns:
   - Detect components in architecture descriptions
   - Parse component relationships (uses, depends on, calls)
   - Extract component types (service, database, queue, cache)

2. **Improve `_generate_architecture_mermaid()`**: Generate better Mermaid diagrams:
   - Use different node shapes for different component types (database uses `[(Database)]`, queue uses `([Queue])`)
   - Detect relationships from content instead of sequential connections
   - Add subgraphs for layers (frontend, backend, data)
   - Include more descriptive labels on connections

3. **Improve `_generate_api_mermaid()`**: Create more detailed API diagrams:
   - Group endpoints by resource (all `/users` endpoints together)
   - Show request/response flow
   - Include authentication requirements if mentioned

4. **Improve `_generate_data_model_mermaid()`**: Generate better ER diagrams:
   - Extract field types from content (string, int, date)
   - Detect relationships (one-to-many, many-to-many)
   - Include foreign keys and indexes

5. **Add Configuration Options**: Allow customization of diagram styles, colors, and sizes.


### Pipeline Enhancement Architecture

**Enhanced Diagram Generation Pipeline:**

```
1. Document Analysis (DiagramGenerationService)
   ↓
   - Analyze sections with improved pattern matching
   - Detect diagram opportunities with higher accuracy
   - Extract components, entities, endpoints with relationship detection
   ↓
2. Diagram Specification Creation
   ↓
   - Generate diagram specs with metadata
   - Include extracted components and relationships
   ↓
3. Mermaid Code Generation (NEW - called in DocumentEnhancementService)
   ↓
   - Generate Mermaid code from spec
   - Apply style and formatting rules
   - Optimize for readability
   ↓
4. Diagram Caching Check (NEW - in RenderingService)
   ↓
   - Hash Mermaid code (MD5)
   - Check cache directory for existing image
   - Skip conversion if cached
   ↓
5. Mermaid-to-Image Conversion (NEW - with fallbacks)
   ↓
   - Primary: Mermaid.ink API
   - Fallback 1: Kroki API
   - Fallback 2: Local Mermaid CLI
   - Log failures and continue
   ↓
6. Diagram Placement (NEW - in RenderingService)
   ↓
   - Map diagrams to sections using section_ref
   - Insert images after section headings
   - Apply proper sizing and spacing
   ↓
7. PDF Generation (Modified - both ReportLab and WeasyPrint)
   ↓
   - Render text content as before
   - Embed diagram images at appropriate locations
   - Maintain existing styling and layout
```

## Testing Strategy

### Validation Approach

The testing strategy follows a two-phase approach: first, surface counterexamples that demonstrate the bug on unfixed code (diagrams missing from PDFs), then verify the fix works correctly (diagrams appear in PDFs) and preserves existing behavior (text-only PDFs unchanged).

### Exploratory Bug Condition Checking

**Goal**: Surface counterexamples that demonstrate the bug BEFORE implementing the fix. Confirm or refute the root cause analysis (RenderingService ignores diagrams array). If we refute, we will need to re-hypothesize.

**Test Plan**: Create enhanced documents with diagram specifications (with Mermaid code populated), pass them to the UNFIXED `RenderingService.render()`, and inspect the generated PDF to verify diagrams are missing. Run these tests on the UNFIXED code to observe failures and understand the root cause.

**Test Cases**:
1. **Single Architecture Diagram Test**: Create enhanced document with one architecture diagram spec (with Mermaid code). Generate PDF with unfixed rendering service. Inspect PDF to confirm diagram is missing (will fail on unfixed code - expected).

2. **Multiple Diagram Types Test**: Create enhanced document with architecture, API, and data model diagram specs. Generate PDF with unfixed service. Inspect PDF to confirm all diagrams are missing (will fail on unfixed code - expected).

3. **Diagram with Section Reference Test**: Create enhanced document where diagram has `section_ref` pointing to existing section. Generate PDF. Confirm diagram is not placed near the section (will fail on unfixed code - expected).

4. **Empty Diagrams Array Test**: Create enhanced document with `diagrams: []`. Generate PDF. Confirm PDF renders successfully with text-only content (should pass on unfixed code - validates preservation).


**Expected Counterexamples**:
- PDFs generated from enhanced documents with diagrams contain zero diagram images
- The `diagrams` array in the enhanced document is completely ignored
- No errors are raised - PDFs generate successfully but are missing expected diagrams
- Possible causes: Missing diagram processing code, missing Mermaid conversion, missing image embedding

### Fix Checking

**Goal**: Verify that for all inputs where the bug condition holds (enhanced documents with non-empty diagrams array), the fixed rendering service produces PDFs with diagrams correctly embedded.

**Pseudocode:**
```python
FOR ALL enhanced_doc WHERE isBugCondition(enhanced_doc) DO
  # Ensure diagrams have Mermaid code populated
  FOR diagram IN enhanced_doc["diagrams"] DO
    ASSERT diagram["mermaid_code"] is not None
  END FOR
  
  # Render PDF with FIXED service
  result := render_fixed(enhanced_doc)
  pdf_path := result["pdf_path"]
  
  # Verify expected behavior
  ASSERT pdf_path exists
  ASSERT pdf_contains_images(pdf_path)  # Check PDF has embedded images
  ASSERT image_count(pdf_path) >= len(enhanced_doc["diagrams"])
  ASSERT no_rendering_errors_logged()
END FOR
```


### Preservation Checking

**Goal**: Verify that for all inputs where the bug condition does NOT hold (documents without diagrams), the fixed rendering service produces exactly the same PDF as the original service.

**Pseudocode:**
```python
FOR ALL enhanced_doc WHERE NOT isBugCondition(enhanced_doc) DO
  # enhanced_doc has either no diagrams key or empty diagrams array
  
  # Render with UNFIXED service
  result_unfixed := render_unfixed(enhanced_doc)
  
  # Render with FIXED service
  result_fixed := render_fixed(enhanced_doc)
  
  # Compare outputs
  ASSERT pdf_content_identical(result_unfixed["pdf_path"], result_fixed["pdf_path"])
  ASSERT same_text_content(result_unfixed, result_fixed)
  ASSERT same_styling(result_unfixed, result_fixed)
  ASSERT same_layout(result_unfixed, result_fixed)
END FOR
```

**Testing Approach**: Property-based testing is recommended for preservation checking because:
- It generates many test cases automatically across the input domain (various document structures, section types, content lengths)
- It catches edge cases that manual unit tests might miss (empty sections, special characters, very long content)
- It provides strong guarantees that text-only rendering behavior is unchanged for all non-buggy inputs

**Test Plan**: Observe behavior on UNFIXED code first for text-only documents, then write property-based tests capturing that behavior.


**Test Cases**:
1. **Text-Only Document Preservation**: Create document with sections but no diagrams. Render with unfixed service and capture output. Render with fixed service. Compare PDFs byte-by-byte or extract text and verify identical (should pass - confirms no regressions).

2. **Empty Diagrams Array Preservation**: Create document with `diagrams: []`. Render with both services. Verify identical output (should pass - confirms empty array handling is unchanged).

3. **Missing Diagrams Key Preservation**: Create document without diagrams key at all. Render with both services. Verify identical output (should pass - confirms backward compatibility).

4. **Complex Document Preservation**: Create document with multiple section types (task, user_story, design_decision), table of contents, abstract, and metadata. No diagrams. Verify fixed service produces identical PDF (should pass - confirms preservation of complex layouts).

5. **Special Characters Preservation**: Create document with special characters, code blocks, lists, and formatting. No diagrams. Verify fixed service preserves all formatting (should pass - confirms text processing unchanged).
