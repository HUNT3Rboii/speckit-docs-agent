# Design Document: PDF Visualization Frontend

## Overview

The PDF Visualization Frontend is a modern React-based single-page application (SPA) that provides users with a visual interface to browse, search, and view PDF documents generated by the Speckit Auto-AI backend. The frontend integrates with the existing FastAPI backend through REST API endpoints and presents PDF artifacts in an organized, searchable dashboard with rich metadata display.

### Goals

- Provide an intuitive, responsive web interface for viewing generated PDFs
- Enable quick discovery through search, filtering, and categorization
- Display rich metadata including titles, types, timestamps, and source paths
- Support version history navigation for artifacts
- Ensure seamless integration with existing backend APIs
- Maintain a consistent, professional design using shadcn/ui component library

### Non-Goals

- PDF editing or annotation capabilities
- User authentication and authorization (phase 1)
- Real-time collaboration features
- PDF generation or processing (handled by backend)
- Mobile native applications (web-responsive only)

### Technology Stack

- **Framework**: React 18 with TypeScript
- **Build Tool**: Vite
- **Routing**: React Router v6
- **State Management**: React Query (TanStack Query) for server state
- **UI Components**: shadcn/ui (Radix UI primitives + Tailwind CSS)
- **Styling**: Tailwind CSS
- **HTTP Client**: Axios
- **PDF Rendering**: react-pdf or PDF.js
- **Date Formatting**: date-fns
- **Type Safety**: TypeScript with strict mode

### Design Patterns

1. **Container/Presentational Pattern**: Separate data fetching logic from presentation
2. **Composition**: Build complex UIs from small, reusable components
3. **Custom Hooks**: Encapsulate reusable stateful logic (e.g., `useProjects`, `useArtifacts`)
4. **Error Boundaries**: Graceful error handling at component boundaries
5. **Suspense**: Loading states with React Suspense and React Query

## API Client Layer

### APIClient Class

```typescript
class APIClient {
  private axiosInstance: AxiosInstance;
  private apiKey: string;
  
  constructor(baseURL: string, apiKey: string);
  
  // Project endpoints
  async getProjects(): Promise<Project[]>;
  async createProject(name: string, repoUrl?: string): Promise<Project>;
  
  // Artifact endpoints
  async getArtifacts(projectId: string): Promise<Artifact[]>;
  
  // Version endpoints
  async getVersions(artifactId: string): Promise<Version[]>;
  
  // PDF download
  async downloadPDF(versionId: string): Promise<Blob>;
}
```

**Key Features**:
- Axios instance with base URL configuration
- Automatic API key injection in Authorization header
- Request/response interceptors for error handling
- 30-second timeout on all requests
- Typed responses using TypeScript generics

### Error Handling Strategy

```typescript
class APIError extends Error {
  constructor(
    public statusCode: number,
    public message: string,
    public details?: any
  ) {
    super(message);
  }
}

function handleAPIError(error: AxiosError): APIError {
  if (!error.response) {
    return new APIError(0, 'Backend server is not available. Please ensure the backend is running.');
  }
  
  const status = error.response.status;
  
  switch (status) {
    case 401:
      return new APIError(401, 'Authentication failed. Please check API key configuration.');
    case 404:
      return new APIError(404, 'Resource not found.');
    case 500:
      return new APIError(500, 'Server error occurred. Please try again later.');
    default:
      return new APIError(status, 'An unexpected error occurred.');
  }
}
```

## Testing Strategy

Since this is a frontend web application with React components, API integration, and UI rendering, **property-based testing is not appropriate**. Instead, the testing strategy focuses on:

### Unit Testing

**Test Framework**: Vitest (fast, Vite-native test runner)
**Component Testing**: React Testing Library

**Unit Test Coverage**:
1. **Component Logic**:
   - Rendering with different prop combinations
   - Event handlers (clicks, input changes)
   - Conditional rendering (loading, error, empty states)
   - Component composition

2. **Custom Hooks**:
   - Data fetching hooks with mocked API responses
   - Debounce hook timing behavior
   - State management logic

3. **Utility Functions**:
   - Date formatting functions
   - Filter/search algorithms
   - URL construction helpers
   - Error message mapping

4. **API Client**:
   - Request construction (headers, body, params)
   - Response parsing
   - Error handling and transformation
   - Timeout behavior

**Example Unit Tests**:

## Accessibility

### WCAG AA Compliance Goals

1. **Keyboard Navigation**:
   - All interactive elements accessible via Tab key
   - Focus indicators visible on all focusable elements
   - Skip to main content link

2. **Screen Reader Support**:
   - Semantic HTML elements (nav, main, article, aside)
   - ARIA labels for icon-only buttons
   - ARIA live regions for dynamic content updates

3. **Color Contrast**:
   - Minimum 4.5:1 contrast ratio for normal text
   - Minimum 3:1 contrast ratio for large text
   - Color not the only means of conveying information (use icons + text)

4. **Responsive Text**:
   - Support browser zoom up to 200%
   - Relative font sizes (rem/em)

### Accessibility Testing

- **Automated**: axe-core, eslint-plugin-jsx-a11y
- **Manual**: Keyboard navigation testing, screen reader testing (NVDA/VoiceOver)

## Performance Optimization

### Code Splitting

- Route-based code splitting (lazy load pages)
- Component-level code splitting for heavy components (e.g., PDF viewer)
- Vendor chunk separation (React, UI libraries)

### Asset Optimization

- Image optimization (WebP format with fallbacks)
- SVG icons (inline for small icons, lazy load for large icon sets)
- Font subsetting (only include used character ranges)

### Caching Strategy

- **API Responses**: React Query with stale-while-revalidate
  - Projects: 5 minute cache
  - Artifacts: 2 minute cache
  - Versions: 5 minute cache
- **Static Assets**: Aggressive browser caching with cache busting (Vite hash)

### Performance Metrics Goals

- **First Contentful Paint (FCP)**: < 1.5s
- **Largest Contentful Paint (LCP)**: < 2.5s
- **Time to Interactive (TTI)**: < 3.5s
- **Cumulative Layout Shift (CLS)**: < 0.1

## Conclusion

This design provides a comprehensive blueprint for building a modern, responsive React frontend for the Speckit Auto-AI system. The architecture emphasizes:

- **Separation of concerns** through clear component boundaries
- **Type safety** with TypeScript throughout
- **Maintainability** via reusable components and custom hooks
- **User experience** with responsive design and accessible interfaces
- **Developer experience** with modern tooling (Vite, React Query, shadcn/ui)

The testing strategy focuses on unit tests for components and logic, integration tests for workflows, and acknowledges that property-based testing is not suitable for frontend UI applications. Instead, example-based testing with comprehensive coverage ensures reliability and correctness.
